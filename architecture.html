How zones are implemented

LayerResponsibility
Firewall routerCreates each VLAN gateway, routes between zones, supplies DHCP, applies default-deny ACLs, performs WAN NAT, and holds the WireGuard-subnet return route.
Managed switchCarries tagged VLAN trunks to Proxmox and the access point; assigns untagged access VLANs to ordinary wired ports.
ProxmoxMakes vmbr0 VLAN-aware, places host management on VLAN 10, and assigns one VLAN tag to each VM NIC.
Guest VMReceives a normal untagged VirtIO NIC, IP address, and VLAN gateway; no VLAN configuration is required inside a single-zone guest.
Proxmox firewallAdds per-VM defense in depth if router rules are absent or misconfigured.
Wireless APMaps trusted and IoT SSIDs to their VLANs. Wireless management remains on VLAN 10.

Applications

WireGuard + AdGuard

WireGuard is the sole remote ingress. AdGuard provides DNS to VPN clients and selected local devices.

No application is exposed directly to the public internet.

Durable: VPN identities, peer assignments, DNS rules, credentials. Deployment: native WireGuard plus an Ansible-managed AdGuard Compose project.

Nextcloud + Gitea + Vaultwarden

These applications share one VM-level trust, maintenance, and failure boundary to reduce host memory use. Each runs as a separate Compose project with its own container network, secrets, and ZFS-backed dataset.

Nextcloud durable state: files, database, configuration, and encryption material. Gitea durable state: repositories, LFS, packages, artifacts, configuration, and database. Vaultwarden durable state: database, keys, attachments, and configuration.

Private clients reach only published application ports. Agents receive network access only to Gitea's HTTPS and SSH endpoints, not Nextcloud, Vaultwarden, or the container networks.

Runner boundary: CI jobs never execute on this VM or on lab-agents-01. A future lab-runner-01 is disposable and receives no application datasets. Gitea documents that host mode has no job isolation and Docker mode shares its daemon; runner isolation is an explicit security boundary.

Hermes Agent

Initial agent runtime. This VM may host future agents, but it never accepts CI runner jobs.

Durable: agent configuration, credentials, sessions, skills. Deployment: Ansible-managed Docker Compose. Boundary: no direct access to Vaultwarden, Nextcloud, or Proxmox management. Outbound HTTPS is required for model and tool providers.

Shared deployment contract

  1. Packer builds the generic Ubuntu image.
  2. Terraform creates each VM, OS disk, network attachment, and data attachment.
  3. Ansible installs and configures applications.
  4. Application data is restored or mounted from ZFS-backed storage.
